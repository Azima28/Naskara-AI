# Generator Laporan PKL — Web App

Web app local-first yang mengubah aset skill yang sudah ada (data schema, katalog, helper python-docx, validator) jadi produk berkualitas hosted: frontend React + Vite + TypeScript, backend FastAPI, akun + draft tersimpan, **9router** sebagai model AI lokal, dan alur kerja **AI draft → review & edit di app** → generate .docx.

## Arsitektur (keputusan sudah dikunci)

| Keputusan | Pilihan |
|---|---|
| Cara jalan | **Local-first** — jalan di laptop kamu; hosting multi-user fase berikutnya |
| Frontend | **React + Vite + TypeScript** |
| Backend | **FastAPI** (Python) |
| Model AI | **9router** (lokal) — diakses lewat abstraksi provider yang menunjuk endpoint OpenAI-compatible, jadi tinggal colok via env config |
| Penyimpanan | **Akun + draft tersimpan** — SQLite sekarang (tanpa server DB terpisah untuk local-first; ganti ke Postgres nanti cukup ubah satu config) |
| Alur konten BAB | **AI draft → review & edit di app** → generate .docx |

## Peta reuse — aset yang sudah ada → kode baru

Ini kerjaan port + extend, bukan dari nol. Aset yang ada jadi sumber kebenaran:

| Aset yang sudah ada | Menjadi | Strategi reuse |
|---|---|---|
| `scripts/validate_pkl_data.py` | `backend/app/validation.py` | **Import apa adanya** — `validate()` + `recommend_bab()` sudah return tuple bersih |
| `references/data-schema.md` + `examples/sample-pkl-data.json` | TS types + model Pydantic | Transkripsi model 18-key; JSON contoh jadi seed/test fixture |
| `references/docx-helpers-pkl.md` (~26KB, kode asli) | `backend/app/docx/builder.py` | **Refactor**: hapus global `doc`; bungkus semua fungsi jadi class stateless `PklDocBuilder` yang pegang state `doc`. Semua nilai presisi (tab 11.83/9.84cm, spacing 1.9, leader TOC 13.5cm) dipertahankan |
| `references/bab-catalog.md` (aturan prosa) | `backend/app/docx/assembly.py` | **Kode baru**: kodifikasi pemilihan 7-modul + struktur sub-bab + penomoran ulang (Roman untuk front matter → Arabic untuk body) jadi fungsi `assemble_report()` beneran |
| `references/front-matter-catalog.md` | `backend/app/docx/assembly.py` | Urutan + skema penomoran halaman (tanpa nomor → lowerRoman → arabic dengan page break switch) |
| `references/jurusan-knowledge.md` | `backend/app/prompts/jurusan/` | **Konteks AI**: di-load per-request sebagai fragmen prompt (template studi kasus, glosarium) supaya konten BAB spesifik per jurusan |
| `references/indonesian-akademik-humanis.md` | `backend/app/prompts/` + frontend highlighter | Batasan prompt + highlighter "frasa anti-AI" di editor pasca-draft |
| `references/formatting-defaults.md` | default `backend/app/config.py` | Preset margin, TNR 12pt, 1.5, justify, aturan enumerasi |

## Dua masalah teknis yang dipecahkan rencana ini

1. **Helper itu kode script global-state.** Semua mutasi satu `doc` level-modul — rusak untuk web server konkuren. → Refactor jadi `PklDocBuilder` (tiap request dapat instancenya sendiri).
2. **Tidak ada assembler.** Helper membangun elemen atomik (satu heading, satu tabel, satu cover); tidak ada yang menyusun "BAB I + sub-bab 1.1–1.8 berurutan." Logika itu cuma ada sebagai prosa di `bab-catalog.md` yang ditujukan untuk LLM tafsirkan. → Tulis `assembly.py` deterministik supaya .docx tidak bergantung pada AI untuk struktur (cuma untuk prosa).

## Urutan build bertahap (tiap fase menghasilkan sesuatu yang bisa jalan)

**Fase 0 — Scaffold & kontrak data**
- Skeleton backend: FastAPI, config, db SQLite, `/health`.
- Skeleton frontend: Vite+React+TS, router, API client bertipe, dev proxy ke backend.
- Port `data-schema.md` → `backend/app/schemas.py` (Pydantic) + `frontend/src/types/`.
- Import validator apa adanya; expose `POST /validate` return skor 20-poin + issues/warnings.
- *Test:* POST JSON contoh → dapat `100%` / "SIAP".

**Fase 1 — Akun & draft**
- Model `User` + `Draft`, auth JWT, register/login/me.
- CRUD Draft: buat, list, get, update (autosave), hapus.
- Halaman auth frontend + Dashboard daftar draft.
- *Test:* login, buat draft, reload halaman, draft masih ada.

**Fase 2 — Form wizard** (bagian frontend terbesar)
- `Wizard.tsx` 11 langkah mirror model data (config → siswa → sekolah → perusahaan → pkl → profil → kegiatan → studi_kasus → peralatan/kendala → closing → assets).
- Komponen `ArrayField` reusable untuk array nested (kegiatan→tugas, jam_kerja, job_descriptions, daftar_pustaka, dll).
- `CompletenessBar` mirror 9 gate WAJIB validator + skor 20-poin live; tombol "Generate" disabled sampai WAJIB terpenuhi.
- Drag-and-drop gambar → `POST /uploads` → entry registry asset (A-001…).
- Autosave ke draft saat berubah (debounced).
- Panel rekomendasi BAB: tampilkan hasil `recommend_bab()` + kontrol override (tambah/hapus modul, set jumlah).
- *Test:* isi data minimal → completeness naik; load contoh lengkap → 100%.

**Fase 3 — Pipeline docx** (backend; frontend pasang tombol Download)
- Refactor `docx-helpers-pkl.md` → `docx/builder.py` `PklDocBuilder` (stateless per-request, semua helper jadi method pada class yang pegang `doc`).
- Tulis `docx/assembly.py`: `assemble_report(data, bab_modules, front_matter_modules)` → susun cover → front matter (roman) → switch page-break → BAB (arabic) → daftar pustaka, pakai builder. Ini kodifikasi `front-matter-catalog.md` + `bab-catalog.md` sebagai Python deterministik.
- `POST /generate`: re-validate → assemble → return stream `.docx` (tempfile + cleanup).
- *Test:* generate dari `sample-pkl-data.json`, buka di Word, bandingkan struktur/presisi secara visual dengan `LAPORAN PKL NIKEN FIXED.docx` (tab stop, spacing, skema penomoran).

**Fase 4 — Integrasi AI**
- `ai/provider.py`: abstrak `generate(system, user) -> str`; `ai/client.py` client httpx menunjuk 9router (base URL + model configurable). Asumsi default OpenAI-compatible `/v1/chat/completions`; terisolasi jadi kalau format beda gak merembet ke mana-mana.
- `prompts/`: system prompt bawa golden rules (semangat TNR, TANPA bullets — cuma `1.2.3.`/`a.b.c.`, anti-generic), template per-section, dan fragmen jurusan di-load dari `jurusan-knowledge.md`.
- `POST /ai/draft-section` dan `/ai/regenerate` (return text saja — tidak menulis .docx).
- Frontend `Editor.tsx`: setelah wizard, tampilkan satu panel editable per section BAB; masing-masing pre-fill oleh draf AI dengan tombol "✨ Regenerate"; fakta terstruktur (kegiatan, kendala) di-merge sebagai list bebas-bullet fixed yang juga bisa di-edit user.
- *Test:* generate Latar Belakang untuk contoh AKL → spesifik jurusan, tanpa bullet.

**Fase 5 — Polish**
- Highlighter anti-AI di editor (port frasa ditandai `indonesian-akademik-humanis.md` → saran underline).
- Panel Settings: preset margin (Default 4-4-3-3 / Standar B / C / Custom), override font/spacing, skip halaman front-matter.
- Re-validate sebelum download; tampilkan warning inline.
- README: instruksi jalan local, config env 9router, cara ganti DB ke Postgres / AI ke cloud nanti.

## Catatan & asumsi
- Saya asumsikan 9router expose **endpoint chat OpenAI-compatible**; abstraksi provider berarti ketidakcocokan format cuma ubah satu file, bukan redesain.
- SQLite dipilih untuk local-first (tanpa beban install); model pakai SQLAlchemy jadi ganti ke Postgres cuma ubah connection-string.
- File reference `.legacy.md` tidak disentuh/diabaikan.
- `references/`, `scripts/`, `examples/` yang ada tetap jadi sumber kanonik — kode baru membaca/transkripsi dari sana, bukan duplikasi pengetahuan.

## Yang dibangun di akhir
App lokal yang kamu jalan dengan dua perintah (`uvicorn` + `npm run dev`): daftar → isi wizard 11 langkah → lihat completeness live → AI draf tiap section BAB → review/edit di app → download `.docx` yang presisi formatnya, dengan draft tersimpan di akun kamu.
